# Slide spine

Every deck follows the same spine so a returning reader knows where to look. Audience changes depth and vocabulary (see `audiences.md`), not the order.

1. **Title + period** ("Progress since <last report date>").
2. **Since last time:** each promise from the previous `state.md` with a status mark (done / changed / dropped / still open) and one line of evidence.
3. **The problem in one picture** (A, B: full slide; C: half slide or appendix). Why hit finding across detectors is hard.
4. **What we did this period:** 3-5 items, outcome first.
5. **Results:** the headline result with its uncertainty (seeds, folds). One main figure per slide, plain titles that state the finding ("Self-supervised model closes the gap on Eiger4M").
6. **What did not work / is unresolved:** shown, not buried.
7. **Decisions and help needed** from this audience.
8. **Next period:** promises that go into `state.md`.
9. **Appendix** (C especially): per-fold tables, setup, ablations.

Speaker notes carry the detail and the source of each number (run name, PR, date). Titles are claims, not topics. One idea per slide.
